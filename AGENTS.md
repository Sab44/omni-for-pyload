# AGENTS.md

Omni is a Flutter client for self-hosted [pyLoad](https://github.com/pyload/pyload) instances (requires pyLoad `0.5.0b3.dev98`+). It targets Android and iOS. Written in Dart, plus Kotlin for one Android-only foreground service.

## Commands

| Task | Command |
|---|---|
| Install deps | `flutter pub get` |
| Run tests | `flutter test` |
| Lint | `flutter analyze` (rules: `flutter_lints`; `packages/openapi_client/**` excluded) |
| Format | `dart format lib test` (never format `packages/openapi_client`) |
| Regenerate mocks | `dart run build_runner build` |
| Release builds | `flutter build apk --release` / `flutter build ios --release --no-codesign` |

## Layout

| Path | Contents |
|---|---|
| `lib/main.dart` | Entry: sets up DI, loads `AppSettings`, runs `App` |
| `lib/core/` | `service_locator.dart` (get_it), `logging.dart` (root logger setup), `polling/` (`Poller`, `ScreenVisibility` + global `routeObserver`), `utils/` (`HttpClientFactory`, formatting) |
| `lib/domain/models/` | Plain immutable Dart models: `Server`, `ServerId`, `ClickNLoadServer`, `AppSettings` (manual `toJson`/`fromJson`/`copyWith`) |
| `lib/domain/repositories/` | Repository interfaces (`I*Repository`) |
| `lib/data/repositories/` | Implementations of the interfaces |
| `lib/features/app.dart` | `MaterialApp`, light/dark themes, routes, global `themeNotifier` |
| `lib/features/<feature>/ui/` | Screens and bottom sheets (StatefulWidgets) |
| `lib/features/<feature>/viewmodel/` | `ChangeNotifier` view models |
| `lib/features/<feature>/services/` | Services (see Architecture). `click_n_load/services/`: `ClickNLoadController` (app-scoped), `ClickNLoadProxy` (local HTTP server), `ClickNLoadPlatform` (native service port + Android adapter) |
| `packages/openapi_client/` | **Generated** pyLoad REST client (`PyLoadRESTApi`). Do not edit or format by hand |
| `android/` | Gradle 9.4.1, AGP 9.2.1, Kotlin 2.4.0, Java/JVM target 17. Needs JDK 17+. minSdk 24 / targetSdk 36 (Flutter defaults); compileSdk 37 (required by `permission_handler_android`, `flutter_secure_storage`). Built-in Kotlin enabled (AGP default); plugins must support it, otherwise they apply KGP and the build warns |
| `android/app/src/main/kotlin/.../` | `MainActivity` (method channel), `ClickNLoadForegroundService` |
| `ios/` | Plugins integrated via Swift Package Manager only (no CocoaPods/Podfile). Min iOS 15.0. All plugins are local packages, so Xcode creates no `Package.resolved` |
| `ios/AltStoreSource.json` | AltStore/SideStore source; new versions are added by the release workflow |
| `test/features/<feature>/{viewmodel,services}/` | View model and service unit tests; `*.mocks.dart` are generated by mockito; hand-written fakes for ports sit in `test/features/<feature>/` |

## Architecture

- Layering: `UI → ViewModel → [Service] → I*Repository (domain) → Repository (data) → openapi_client / storage`. Each layer calls only layers to its right; the service layer is optional.
- Pattern: MVVM. The UI talks only to its view model. Each screen creates its view model in `initState`, injecting dependencies via `getIt<...>()`, and calls `setState` from an `addListener` callback. View models own screen state; they reach repositories directly or through a service. No Provider/Bloc/Riverpod.
- Services (`features/<feature>/services/`) hold state or side effects that outlive one screen or are shared by several view models (example: `ClickNLoadController`). A service is a deep module: small interface, may own resources (servers, timers, platform channels) and use repositories, including writes. It exposes state as a `ChangeNotifier` that view models listen to; it never touches widgets or `BuildContext`. Platform-specific code sits behind a port (abstract class) with an adapter per platform; the platform choice is made once, in `service_locator.dart`.
- DI (`core/service_locator.dart`): singletons for `IServerRepository`, `IPyLoadApiRepository`, `ISettingsRepository`, `IAppInfoRepository` (app version via `package_info_plus`), `ILocalNetworkRepository` (iOS local network permission check, opens app settings), `ClickNLoadController` (the only Click'N'Load instance). Services are registered by concrete type when their seam is a port; repositories by interface.
- Navigation: named routes in `app.dart`. `/server`, `/settings`, `/download-detail` take arguments via `onGenerateRoute` (`Server`, or a `Map<String, dynamic>`).

### Features

| Feature | Purpose |
|---|---|
| `server_overview` | List of saved servers with live status; start screen (optionally auto-opens the only server). Per-server menu: edit, remove |
| `add_server` | Add server form, also used to edit a server (`/edit-server` route, `AddServerScreen(server:)`). Same validation for both; validates connection via API before saving. `ScanServerQrScreen` (`/scan-server-qr`, `mobile_scanner`) adds a server from the QR code in pyLoad's web UI. "Add new server" in `server_overview` lets the user pick QR or manual |
| `server` | Main per-server screen: tabs Overview (active downloads) / Queue / Collector, multi-select actions, add links, upload DLC, Click'N'Load control |
| `download_detail` | Package details incl. files, package password |
| `settings` | Theme, start-screen behavior, per-server Click'N'Load config, About section (app version) |
| `click_n_load` | Bottom sheet to configure Click'N'Load target; `ClickNLoadController` shared by `server` and `settings` |
| `error_dialog` | Shared error dialog |

### Data and networking

| Concern | Implementation |
|---|---|
| Server list | `shared_preferences` key `servers` (JSON), written only via `_saveServers`, which strips API keys. Editing uses `replaceServer(originalId, updated)`: keeps list position, moves the API key if IP/port changed. The repository is the source of truth: screens re-read via `getServer(id)` after changes instead of sharing `Server` instances |
| API keys | `flutter_secure_storage`, key `server_credentials:<ip>:<port>`. Servers are identified by `ServerId` (`ip` + `port`, `Server.id`); use it for every "same server?" check |
| App settings | `shared_preferences` key `app_settings` (JSON) |
| pyLoad API | `PyLoadApiRepository` wraps `PyLoadRESTApi`; auth header `X-API-Key`; base URL `<protocol>://<ip>:<port>`; one connection (API + `http.Client`) pooled per `ServerId`, replaced when key / protocol / TLS setting change (the old client is closed once its running requests finished); tests inject `createClient` (`MockClient`) |
| Errors | Repository methods fail only with a sealed `PyLoadApiFailure` (`domain/models/pyload_api_failure.dart`: unauthorized / timeout / unreachable / server error / bad response); its `message` is the single source of user-facing text. Requests time out after 2 s. Bulk actions (restart, move, extract) run per package and return `Result { success, partial, failure }` |
| iOS local network permission | No query API exists. Before the connection test, `AddServerViewModel` calls method channel `com.downloader.omni_for_pyload/local_network` (`checkAccess`, implemented in `AppDelegate.swift`): opens an `NWConnection` to the server and checks for `localNetworkDenied`, waiting for the user's answer while the system prompt is shown. Denied → `LocalNetworkAccessDeniedException`, dialog offers "Open Settings" |
| Self-signed TLS | `Server.allowInsecure` → `HttpClientFactory.createClient(true)` disables cert validation |

### Polling (no push/websocket)

| Where | Interval (after the previous request finished) |
|---|---|
| Server status (`ServerViewModel`, `ServerOverviewViewModel`) | 2 s |
| Active downloads tab | 1 s |
| Queue / Collector tabs | 10 s |

- All polling runs through `Poller` (`core/polling/poller.dart`): fetch right away, then again one interval after each fetch finished (requests never overlap). `start`/`stop` choose what is polled, `pause`/`resume` follow visibility, `refresh` fetches now. Results of overtaken fetches are dropped, so nothing is delivered after `dispose`. `retryNowOn` skips the wait for matching errors (the overview retries right after a `PyLoadApiTimeout`).
- `ServerViewModel` keeps one poller per `ServerTab` (`overview` / `queue` / `collector`, enum in `server/viewmodel/server_tab.dart`); only the selected tab's poller is started. Adding links or uploading a DLC refreshes the tab of that `Destination`. `ServerOverviewViewModel` keeps one poller per server, replaced when the server is edited.
- Polling pauses when the app is backgrounded or the route is covered: screens mix in `ScreenVisibility` (app lifecycle + `routeObserver`) and forward `onVisibilityChanged` to the view model's `pausePolling` / `resumePolling`.

### Click'N'Load (Android only)

- `ClickNLoadController` (DI singleton) owns the proxy, the native service and the state (`ClickNLoadStopped` / `ClickNLoadRunning(serverId, target)` / `ClickNLoadUnsupported`). Interface: `start(serverId)` (reads the stored config, so a removed server or cleared config reports `notConfigured`), `stop()`, `stopFor(serverId)`, `reconfigure(serverId, config)` (stops if running for that server, persists via `IServerRepository`, restarts against the new target; `null` clears and stops). Operations are serialized. `ServerViewModel` listens to it and stops it when the server screen is left; `ServerOverviewViewModel.removeServer` stops it for the removed server.
- `ClickNLoadProxy` starts a `shelf` HTTP server on port `9666`, forwards `/flash/*` to the target via an injected `http.Client` and answers `/jdcheck.js` itself.
- `ClickNLoadPlatform` is the port to the native service: `AndroidClickNLoadPlatform` (requests notification permission, method channel), `UnsupportedClickNLoadPlatform` (iOS). Tests use `test/features/click_n_load/fake_click_n_load_platform.dart` and proxies on port `0`.
- Method channel `com.downloader.omni_for_pyload/click_n_load`:
  - Dart → Kotlin: `startService`, `stopService`, `isRunning`
  - Kotlin → Dart: `onServiceStopped` (e.g. stopped from the notification)
- `ClickNLoadForegroundService` (type `dataSync`) keeps the process alive.

## Conventions

- Add new screens as `lib/features/<name>/{ui,viewmodel}/`. Keep logic in the view model; UI reads getters and calls methods.
- New repositories: interface in `domain/repositories/`, implementation in `data/repositories/`, register in `service_locator.dart`.
- New services: `lib/features/<feature>/services/`, register in `service_locator.dart` when app-scoped. Put the test seam at the service's outer edge: a port with an in-memory fake (platform, network) or an injected `http.Client` (`MockClient`), so view model tests can run the real service.
- View models and services take dependencies as constructor parameters so tests can substitute them: repository interfaces (mockito mocks), or a real service built with fakes at its ports. Assign private fields with private named initializing formals (`required this._serverRepository`, passed as `serverRepository:`; Dart 3.13+). Annotate tests with `@GenerateMocks([...])` and regenerate mocks after interface changes. Use `fake_async` for timer-based behavior.
- Logging: no `print`. Use `package:logging` with one logger per class (`static final _log = Logger('ClassName');`). Pass caught errors and stack traces as arguments (`_log.warning('msg', e, stackTrace)`). Levels: `severe` failures, `warning` recoverable errors, `info` lifecycle events, `fine`/`finest` request details. Release builds output `WARNING`+ only (`setupLogging()` in `main.dart`).
- Do not hand-edit or reformat `packages/openapi_client`; it is regenerated from pyLoad's OpenAPI spec.
- Run `dart format lib test` before committing. Do not run `dart format .`, it would also reformat the generated client.

## CI / Release

| Workflow | Trigger | Action |
|---|---|---|
| `flutter-tests.yml` | push / PR to `main` | `flutter test` on latest stable Flutter |
| `build-and-release.yml` | manual (`workflow_dispatch`, input: `prerelease`) | Fails early if tag/release `v<pubspec version>` already exists or `CHANGELOG.md` has no entry for the version. Builds APK + unsigned IPA, creates GitHub release `v<pubspec version>`, then (non-prerelease only) prepends the version to `ios/AltStoreSource.json` and pushes the commit |

Release steps: bump `version` in `pubspec.yaml` → add a `## [<version>] - <YYYY-MM-DD>` section to `CHANGELOG.md` (version without build number) → run release workflow. `.github/scripts/extract_release_notes.sh` extracts the section: as Markdown it heads the GitHub release body (GitHub's generated notes follow below), as plain text (`--plain`) it becomes the AltStore "What's new". The AltStore entry is generated by `.github/scripts/update_altstore_source.sh`: date = release publish time, size = IPA asset size in bytes, min iOS = `MinimumOSVersion` of the built IPA.

Identifiers: Android package `com.downloader.omni_for_pyload`, iOS bundle ID `com.downloader.omniForPyload`.
